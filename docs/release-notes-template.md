# 发布说明模板（启动器内"更新日志"与群公告通用）

> 规则（第 54 轮确立）：
>
> 1. **一句话说人话，不出现技术名词**（不写 EXE / CDN / TTL / Guard，写"程序 / 下载线路 / 30 分钟内"）。
> 2. 修复条目用用户视角：**"修复：XXX 情况下会 YYY"**（"可能""之前会"）。
> 3. 没新功能就坦率写 **"本次无新功能，主要是稳定性与体验修复"**——不心虚。
> 4. 优化只写**用户能感知到的变化**。
> 5. 结尾给行动指引（诊断包）。
> 6. 发布时同步填入：启动器 帮助页 →「更新日志」分类（`HelpContent.cs` 置顶新增一条）。

## 模板（直接套用）

```
【第 X 轮更新】
本次无新功能，主要是稳定性与体验修复：

修复
- 选择游戏版本后，加载器可能"自动变成已选择"，影响你选择其他加载器——现在只有你亲手选择才会选中。
- 设置页在 Java 列表附近滚动时容易被卡住——现在整页滚动都顺畅。
- 有时用到的还是旧版本的启动器——现在每次更新都会附带一个版本信息文件，一看便知。
- 下载模组或前置时，进度可能长期停在 0%、速度极慢——现在会自动改用更快的下载线路。

优化
- 切换游戏版本时，加载器列表 30 分钟内秒开，不联网也能看。
- 页面滚动更流畅（配置较低的电脑更明显）。
- 安装 Fabric 实例时会自动装好 Fabric API 前置，装完会弹提示告诉你（可在设置中关闭）。

如果你遇到问题，可在「设置 → 导出诊断包」，把文件附在反馈里，排查会快很多。
```

## 有新功能时的变体

```
【第 X 轮更新】新功能：一句话说明这个功能对用户的价值

新功能
- （功能名：一句话说它能干什么、在哪找到）

修复
- （同上格式）

优化
- （同上格式）

如果你遇到问题，可在「设置 → 导出诊断包」，把文件附在反馈里，排查会快很多。
```
