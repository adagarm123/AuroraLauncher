# ADR-0004：下载韧性策略（四线路竞速 + 断点失效泛化 + 缓存兜底）

- 状态：已采纳（第 30/39 轮迭代成型）
- 关联轮次：第 27、30、32、35、39 轮

## 背景

中国网络环境下，Mojang 官方源、BMCLAPI 镜像、Fabric/Quilt 元数据各自的
可达性随时变化。第 27 轮前，超时/重试/镜像逻辑散落在至少三处
（单文件下载、资源索引、加载器安装器），任何一处遗漏就是"卡死 0 B/s"或
"阶段无期限等待"。第 30 轮甚至出现**四条线路全部超时**（含 BMCLAPI）的
极端场景。

## 决策

1. **元数据 GET 统一走 NetRouting**（四线路并行竞速：官方默认/直连 +
   BMCLAPI 默认/直连；单线路超时；整体重试一轮；失败聚合报因）。
   第 39 轮完成收敛：manifest、版本 JSON、资源索引、Modrinth、加载器
   元数据全部接入。豁免登记：下载引擎的文件级策略（引擎专属）、OAuth
   POST（无镜像语义）。
2. **断点失效规则泛化**：416 / Content-Range 起点不匹配（容错
   `bytes 0-99/*` 等非标准格式）/ .part ≥ 预期大小 / 哈希不匹配 →
   统一"删 .part 从头重下"；同一文件哈希连续 3 次失败 → 放弃该文件
   （疑似服务器端变更）；重试耗尽 → 可选文件跳过并计数（不阻塞安装）。
   每次失效写日志，便于统计哪些 CDN 容易出问题。
3. **元数据本地缓存兜底**：成功拉取的版本列表 / 最新版本 / profile JSON
   落盘 `cache/installers/`；全线路失败时自动改用上次成功缓存——只要
   曾经成功浏览过，弱网/断网也能完成安装。缓存命中在日志与流程图明确
   标注，不静默降级。
4. **下载引擎专项**：单尝试 25s 空闲超时（挂起连接不再阻塞批次）；
   进度节流 10 次/秒（UI 平滑）；跳过的可选文件计入完成数（剩余归零）。

## 后果

- 正面：真机验证断网/弱网场景可完成安装；"剩余文件 1 永不归零"、
  "0 B/s 假死十分钟"等问题消失；缓存一致性有测试锁定（见 ADR-0001
  的双路径一致性 + 网络对比测试）。
- 代价：策略集中在 NetRouting 与 DownloadEngine 两处，新增请求类型
  必须选择走哪条（GET → NetRouting；大文件 → 引擎；OAuth → 直连+超时），
  已在 ROADMAP 工程债中登记豁免规则。
- 边界：BMCLAPI 为社区服务无 SLA——极端情况元数据仍可能全线路失败，
  此时依赖本地缓存（缓存兜底因此是必需品而非优化）。

## 反例（不采纳此 ADR 的已发生后果）

第 30 轮四条线路全部 8 秒超时（用户网络瞬时波动 + BMCLAPI 限流叠加），
若无整体重试与本地缓存，安装直接失败且无法自救。第 32 轮单个资源
416 空转导致"剩余文件 1"永久卡住。这两类问题在策略收敛后均再未出现。
