# ADR-0021 内容中心状态同源与安全卸载

- 状态：已采纳（含静态防线与离线单测）
- 轮次：第 99 轮（2026-11-15）
- 触发：截图「「光影包」搜索到 141 个结果 / 主页面全白 / CurseForge 子导航假高亮」；同时要求展示缓存文件夹、引导里可选便携模式、一键卸载。

## 背景

内容中心的顶部状态栏是自由文本 `Status`，不是绑定。`SelectContentKindCommand` 对 `CurseForge / OptiFine / 本地管理` 直接返回，既不更新 `Status` 也不触碰右侧主内容区的 DataTrigger；于是「141 个结果」是上一次 Modrinth 搜索的残留文案，与当前视图完全脱节。此外 `SearchContentCommand` 与首次自动搜索都不重置 `ShowContentDetail`，而详情浮层是一块不透明的 `PanelBrush` Border —— 它残留时把列表、空状态、分页栏全部盖住，形成「白板」。子导航的淡紫块则是鼠标悬停，`TextMatchConverter` 本来就只认 `ContentKind`。

代码里其实已有空状态，所以「补一个空状态」不是本次的修复重点；重点是把**状态文字的来源**和**覆盖层生命周期**收敛。

## 决策

1. **状态文字只由列表驱动。** `ContentStatusText` 读 `ModSearchResults.Count`、`_searchTotalHits`、`ContentKind`、`IsSearching`、`ContentSearchError`，页面内也有同源横幅。非 Modrinth 分类返回分类名而不是残留数字。所有搜索入口先 `ShowContentDetail = false`，切分类清掉残留状态与错误。
2. **空状态三态。** 尚未搜索 / 搜索失败（红色 + 重试）/ 本页为空；当 API 返回总数但本页为 0 时，明确解释页码越界或筛选过严并给「回到第一页」。结果区 `MinHeight=200` 作为布局兜底。
3. **高亮与 hover 必须可分。** 复用第 96 轮的 `PageActiveBorderConverter`，8 个子导航都加只由 `ContentKind` 生成的左侧竖条；Guard 锁定每个 Background 都绑同一来源且不得依赖焦点。
4. **缓存是只读清单。** `CacheFolderPolicy` 是唯一目录来源，设置页只展示路径 / 占用 / 打开，绝不在这条路径上删文件；删除仍归第 88 轮的分类清理。
5. **卸载 fail-closed。** `UninstallPolicy` 只把数据根下明确白名单内的启动器条目列入删除计划，未知条目一律保留；`IsSafeRoot` 拒绝驱动器根、系统目录、桌面 / 文档 / 下载。确认窗口逐条列全路径、单独询问存档与 Java（默认保留）、要求勾选不可恢复确认，VM 再弹最后一次确认。执行优先移入回收站；运行中的 EXE 用 `MoveFileEx(DELAY_UNTIL_REBOOT)` 在重启后删除。
6. **便携模式是可逆的显式选择。** 引导里勾选后只写一个 `portable.txt`，不自动搬移已有数据；设置页与引导共用同一个静默核心，避免两套逻辑分叉。

## 权衡

- 卸载不追求「一次点完立刻连 EXE 一起消失」：Windows 锁住正在运行的映像，硬删需要自复制 helper 进程，风险远大于「重启后自动删除」的提示。
- 送回收站意味着磁盘空间不会立即释放，但换来可恢复性；已完成提示里明说这一点。
- 缓存清单固定 6 项而非动态遍历整个数据根：动态遍历会把游戏本体也算成「缓存」，诱导用户误删。

## 验证与已知限制

- `--unit` 154/154、`--all` 161/161；`--cache-scan` 在真实数据根实跑（合计 26.0 MB）。
- **卸载没有在真机执行**（危险操作），只验证了纯策略、路径白名单、危险目录拒绝与静态 Guard。真机确认窗口的路径清单与两次确认手感留给用户实测。
- 内容中心修复是代码与静态防线层面的验证，未做自动化 UI 点击回归；切换分类的手感留给用户实测。
