# ADR-0032：设置页三源网络诊断与图形化测速

- 状态：已采纳（含防线测试）
- 日期：2026-11-27
- 相关：ADR-0030（CNB 主源）、ADR-0031（重试与如实 UI）

## 背景

启动器现在依赖三个主机：CNB 更新源（国内主下载）、GitHub 更新源（签名兜底）、Mojang 官方源（版本清单）。出网络问题时缺少一个让用户自行判断"到底哪个源慢/不通"的入口。已有的 `NetworkProbe` 只做后台两线路择优，结果被缓存且不展示明细。

用户同时指出：对外发布的文档里存在大量第二人称和开发过程口吻（第二人称指令、开发过程叙述与对话式措辞等），不适合发布给所有人看。

## 决策

1. **显式诊断 API**：`NetworkProbe.ProbeDiagnosticsAsync` 并行测三个主机，复用 HEAD→1 字节 GET 的轻量手法（超时 5 秒）。它是**用户主动触发**的诊断，永不读缓存、**不改变** `NetworkProbe.Preference`，因此不影响下载线路。CNB 仓库路径可用环境变量 `AURORA_CNB_REPO` 覆盖，默认 `AuroraLauncher-2026/AuroraLauncher`。
2. **纯函数归一化**：`NormalizeBars` 把延迟换算成 0..100 的条长（最快源满条，其他按 fastest/slowest 缩放，不可达为 0）。它是纯函数，可无网络单测；`HostDiagnostic.BarWidth` 直接给出像素宽，避免 XAML 里再加 converter。
3. **UI**：设置页「网络」卡片新增「网络诊断」按钮（`NetworkDiagnoseCommand`，内置防重入），结果用 `ItemsControl` 渲染三行条形图 + 毫秒数 + 主机名，并显示"最快源"摘要。测试期间按钮变「测试中…」。
4. **文档人称规范**：对外文档统一使用中性/读者视角表述；验证类措辞统一为「建议验证」，其余改为客观叙述。产品界面文案里直接面向用户的「你的令牌字段」等属正常交互文本，保留。

## 后果

- 用户能在设置里自助定位是哪条线路慢/不通，不必靠猜；诊断本身不改变任何网络行为。
- 三源并行，最坏 5 秒返回；只发 HEAD 或 1 字节 GET，流量可忽略。
- 条长是相对值（最快源满条），避免不同网络环境下绝对刻度失去意义；文案里说明"条越短越快"。
- 文档不再出现针对单个读者的口吻，适合公开展示。

## 验证

- `--unit` 186/186、`--all` 193/193；机制防线 69→70。
- 三源诊断本地实跑：Mojang 396 ms / CNB 634 ms / GitHub 1502 ms，条长比例与实测一致。
- 新增防线：三源并行诊断接线、`NormalizeBars` 纯函数（最快满条/慢源按比例/不可达为零）、XAML 按钮与条形绑定。
