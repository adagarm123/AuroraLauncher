# ADR-0022 缺失前置的一键补齐

- 状态：已采纳（含静态防线与离线单测）
- 轮次：第 100 轮（2026-11-16）
- 触发：第 77 轮有体检、第 97 轮修好解析与去重后，用户要求在真实整合包上「一键补齐前置」；ROADMAP 同时留了明确判据——接自动下载前必须先写 fallback 路径与单测。

## 背景

第 97 轮的截图里，Forge 实例报「缺少 19 个前置（29 项）」且含不可能的 `fabric-api`。真因是双元数据 jar：同一个 jar 同时带 `fabric.mod.json` 与 `META-INF/mods.toml`，旧解析器无条件优先读 Fabric 元数据。修完解析并对跨加载器 id 过滤、按 modId 去重后，真实数据从 19 条降到 6 条。用户明确要求「先修解析，再上一键补齐」，所以那一轮只铺了 `VersionRangePolicy` / `PreflightAutoFixPolicy`，没有接下载。

本轮接入下载时，最大的风险不是「能不能搜到」，而是**装错**：Modrinth 搜索的第一个结果可能只是名字相近的另一个模组；没有哈希的 jar 可能损坏或被替换；下载成功也不代表加载器认这个 modId。

## 决策

1. **精确匹配才允许下载。** `MissingDependencyFix.PickProject` 只接受 slug 完全一致（忽略大小写）或标题完全一致（忽略空格 / 标点）；模糊命中返回 null 并报「没找到」。已知 id 用人工核对过的 slug 映射（`kotlinforforge → kotlin-for-forge` 等），其余用字面 id。
2. **四道版本门。** 候选文件必须同时满足：实例加载器标签唯一（Forge 实例绝不产生 `fabric` facet）、MC 版本匹配、**所有**已合并的范围都接受、有 SHA-1 且大小 > 0（`CanVerify`）。-release > beta > alpha 排序，同档取最新发布时间。
3. **重扫是唯一的成功判据。** `AutoFixSession.Complete(presentIds)` 把「下载已完成」的项逐条与重扫得到的 `ModPreflight.Report.PresentIds`（含 `provides` 声明）比对；看不见就降级为 `NotRecognized`。重扫本身失败时传空集合，fail-closed——绝不让「没验证」伪装成「已验证」。
4. **尽力而为，逐项闭环。** 每个前置单独 try/catch；搜索失败、版本不匹配、无校验值、下载失败分别映射到七种 `AutoFixStatus`，每条都有中文文案；失败项一律附「打开 mods 文件夹 + 搜索 slug + 版本范围」的手动出口。整批是一个可取消的 `DownloadJob`，不是全局状态字符串。
5. **双入口、同一核心。** 本地管理页提供持久清单（勾选 / 全选 / 重扫 / 打开文件夹 / 一键补齐），启动前检查窗提供「补齐选中项并继续」。补齐后自动重扫，若仍有问题再弹一次检查窗且 `allowAutoFix=false`，避免对话框死循环。

## 权衡

- **只支持 Modrinth**：CurseForge 的多数项目 `downloadUrl = null`（平台政策），只给手动出口，不假装能自动补齐。
- **不做模糊推荐**：宁可让用户多点两下手动下载，也不能把名字相近的错误模组塞进 mods 目录——那会让之后的每一次崩溃分析都建立在错误的数据上。
- **只认 SHA-1**：Modrinth 版本 API 当前提供的是 SHA-1，下载引擎已有校验链路；没有校验值的文件一律拒绝，即使它看起来是官方的。
- **不自动重启游戏 / 不自动再次启动**：补齐只修改文件，是否继续启动由用户当前所在的流程决定（启动前检查窗会继续，本地管理页不会擅自启动）。

## 验证与已知限制

- `--unit` 162/162、`--all` 169/169；新增 8 项覆盖排序 / slug 精确匹配 / 版本四道门 / 重扫降级 / 七态文案与 3 条静态防线。
- `--auto-fix-scan <实例目录> <加载器> <MC版本>` 只读冒烟：解析真实前置并打印将选择的版本与校验值，不下载、不写 mods。
- **未在真机执行过一次真实的自动补齐**（会改动用户的 mods 目录）；真实整合包上的逐项结果手感留给用户实测。
- 自动补齐后的重扫只是再次读取 jar 元数据，不会启动游戏验证模组间运行时兼容性；依赖声明之外的冲突仍交给启动前体检与崩溃诊断。
