# ADR-0015：命令层防重入（一次只允许一件同样的活）

- 状态：已采纳（第 93 轮，含防线测试）
- 日期：2026-11-15
- 相关：[ADR-0013](ADR-0013-settings-dirty-and-close-gate.md)（关闭闸门）、[ADR-0014](ADR-0014-launch-readiness-and-modpack-expectation.md)（启动闸门）

## 背景

用户点了按钮，界面在 200 ms 内没有可见变化，本能就会再点两下。那三个动作本来无害，问题是它们会**重复触发同一件还没做完的事**：再开一次网络请求、再起一个 `java -version`、再让一个安装器去写同一批文件。

`RelayCommand` 当时没有任何保护，`Execute` 直接把活派下去。更糟的是有三个命令写成「火后不管」：

```csharp
new RelayCommand(_ => _ = CheckForUpdateAsync())   // 命令立刻返回，任务还在跑
```

这种写法连“手动在方法开头加 `if (busy) return;`”都不解决 —— 第二次点击时方法早已返回，`busy` 要么没设、要么已被清掉。

## 决定

### 1. 把「一次只放一个」做成命令的能力，而不是每个按钮的自觉

`RelayCommand` 持有一个 `CommandGate`（`AuroraCore`，纯状态机）：

- `TryEnter()` 用 `Interlocked.CompareExchange` 占位，抢不到就 **把这次点击丢掉并计数**；
- `CanExecute` 在占位期间返回 false → WPF 自动置灰按钮，用户连点也进不到业务代码；
- `finally` 里 `Exit()`，**异常路径同样解锁**（否则按钮永久变灰，比重复执行更难查）；
- 占位/释放时都发 `CanExecuteChanged` + `PropertyChanged(IsRunning)`，并**切回 UI 线程**再发（部分调用点 `ConfigureAwait(false)`，跨线程会抛）。

### 2. 异步命令默认开门，同步命令不开

- 异步命令（40 个）等待期间 UI 线程是空闲的，重复点击完全可能 → 默认 `guardReentry: true`；
- 同步命令在 UI 线程内跑完才可能收到下一次点击，重入不可能 → 不分配门，行为与老版本完全一致（零风险改造）。

### 3. 「火后不管」一律改成真异步命令

守卫扫描所有 ViewModel，禁止 `new RelayCommand(_ => _ = XxxAsync())`。本轮据此抓出三个真 bug：继续下载、导出整合包、检查更新 —— 它们本来完全不受保护。

### 4. 文案要动，不只是灰

灰一下容易被理解成「卡了」。耗时按钮的 `Content` 绑到 `命令.IsRunning`，用已有的 `BoolToText` 转换器扩展出 `ConverterParameter='忙碌|空闲'`（不新增资源键，所有页面与冒烟的资源加载都不用改）：

| 按钮 | 执行中 |
|---|---|
| 扫描未注册实例 | 扫描中… |
| 补全文件 | 补全中… |
| 检查更新 | 检查中… |
| 完成登录 | 登录中… |

## 被否决的方案

- **每个 Click 里写 `if (isClicked) return;`**：40 个命令 × 未来新命令，一定会漏；且「火后不管」写法下根本无效。
- **只加 VM 的 `IsBusy` 判断**：跨命令污染（一个命令忙 → 别的按钮也不能点），而且仍然依赖每个人记得写。
- **拦截 300 ms 内的物理双击**：按钮已按执行状态置灰；再加时间窗会误伤「快速点两个不同按钮」的正常操作，收益为负。
- **全局鼠标 `Wait` 指针**：视觉噪音大，且短任务会出现「闪一下指针」，比不改更烦。

## 后果

- 长任务期间按钮是灰的（这是预期），用户会看到「补全中…」而不是「没反应」。任务卡死时按钮会一直灰 —— 所以异常路径必须解锁，测试已覆盖。
- 命令里未捕获的异常从 `Debug.WriteLine` 改为写日志文件。以前这类异常等于消失，是「什么都没发生」投诉的常见来源。
- `SuppressedClicks` 目前只用于日志与诊断，没有 UI 展示。

## 防线

- `#120` `CommandGate`：单槽语义、计数、Exit 后可再进、**32 线程并发只进一个**、Reset
- `#121` 真实 `RelayCommand`：重入被拒、执行中 `CanExecute=false`、完成后解锁、异常后解锁、同步命令不分配门
- `#122` 源码守卫：必须用门、异步默认开、`IsRunning` 必须发通知、异常必须落日志、**禁止火后不管**、四个耗时按钮必须绑 `IsRunning`、转换器必须支持「忙碌|空闲」
- `--cleanup-smoke` 运行时断言：扫描进行中按钮确实置灰，结束后恢复
