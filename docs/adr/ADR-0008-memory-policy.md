# ADR-0008：内存策略——自动分配有硬上限，清理只碰自己

- 状态：已采纳（含防线测试）
- 日期：2026-11-12
- 关联：第 79 轮（物理内存探测）、第 78 轮（崩溃修复的内存建议）、第 83 轮（本 ADR）

## 背景

"我该分配多少内存"是玩家最常问、也最容易问错的问题。给少了，游戏在载入区块时 OOM；给多了，Windows 开始把正在跑的游戏换页到硬盘，整台电脑像死机一样卡上几分钟——而玩家会认为这是启动器的问题。

同时，"一键释放内存"这类功能在同类软件里很常见，但在"启动器 + JVM"这个组合下几乎总是负优化。

## 决定

### 1. 自动分配，但上限永远赢过推荐值

`MemoryAllocationPolicy.Recommend(physicalMb, modCount, hasShader, modded)`：

1. 按工作负载取基础值：原版 2048；模组 <30 → 3072，<80 → 4096，<160 → 5120，更多 → 6144。
2. 光影把基础值抬到至少 4096（大包 + 光影 7168）。
3. **上限 = 物理内存 × 55%，向下对齐 512 MB，硬顶 16 GB。**
4. 结果取 `min(基础值, 上限)`，再抬到地板 1024（仅当机器负担得起）。
5. 被上限截断时，`Advice.CappedByPhysical = true`，UI 必须解释原因，而不是悄悄给一个小数字。

为什么是 55%：剩下 45% 要留给 Windows、显卡驱动、浏览器和启动器自己。超过 60% 时系统开始明显换页（自测断言所有自动路径 ≤ 60%）。

### 2. 手动值不静默改写

玩家可能比表更懂自己的整合包。手填多少就用多少；只在超过安全上限时**实时红字警告**（不阻止保存）。若在保存时偷偷改成"安全值"，玩家遇到的是"我明明填了 8 GB，为什么还是 OOM"，比一个警告糟得多。

`AutoMemory` 是独立开关，`MaxMemoryMb` 始终保存手动值 —— 关掉自动，回来的是玩家自己那个数字。

### 3. 默认值：老配置不动，新装才开

- 已有 `config.json`（升级用户）：`AutoMemory` 缺省为 `false`，**不改动任何已经能用的设置**。
- 全新安装：首次引导结束（`FinishFirstRun`）时打开自动模式。这是唯一能确定"这是新用户"的时刻。

### 4. 不做"自动清理内存"，只做三件安全的事

- **绝不 trim 游戏进程的工作集**：会触发 stop-the-world 回收，游戏卡 1–2 秒、帧率归零。这是用户能立刻感知的伤害。
- **绝不枚举其他进程**：`EmptyWorkingSet` 遍历进程会把别的程序页出去、又被立刻页回来，净效果是变慢。
- 落地：清自己的图标缓存（只清内存，磁盘缓存保留）+ `SetProcessWorkingSetSize(GetCurrentProcess(), -1, -1)`；手动入口允许一次完整 GC（**只在 `Task.Run` 内**，唯一允许出现 `GC.Collect` 的文件）；托盘闲置 5 分钟清一次缓存（不给强制 GC，避免回窗口时等回收）。
- 结果如实报告："约 23 MB"或"系统可能暂时保留这些页，任务管理器里的数字不一定马上变小"——不编造释放量。

## 后果

- 好：小白不用猜数字；极端机器不会再被"推荐 16 GB"推入交换；"释放内存"按钮不会让游戏掉帧。
- 代价：低内存机器上自动值会明显低于玩家期待（4 GB 机器约 2 GB），需要 UI 解释——由 `Describe` 承担。
- 已知未做：手动值仍全局，没有实例级覆盖；自动模式已按实例的模组/光影计算，但"这个实例想单独固定 8 GB"还需要再加一个字段（见 ROADMAP 功能待办）。

## 防线（测试，不是注释）

1. 全参数扫描（1024–131072 MB × 5 档模组 × 光影 × 原版/模组）：自动结果 ≤ 60%、≤16 GB、≥ 地板、512 整数倍；`SafeCeiling` 自身同样满足。
2. 源码扫描 `MemoryHygiene.cs`：出现 `Process.GetProcesses` / `GetProcessesByName` / `OpenProcess(` / `"javaw"` / `"java"` 即失败；必须是 `SetProcessWorkingSetSize(GetCurrentProcess())`。
3. 整个 Desktop 项目中 `GC.Collect` 只允许出现在 `MemoryHygiene.cs`；VM 必须通过 `Task.Run(() => MemoryHygiene.Trim(...))` 调用（手动与闲置两条路径）。
4. `LauncherService` 必须经 `MemoryAllocationPolicy.Effective` 解析，且 `-Xms` 被 `Math.Min(cfg.MinMemoryMb, maxMemoryMb)` 压住。

## 反例（如果不这么做）

- 若允许自动推荐突破 55%：8 GB 机器给 8 GB，游戏启动后系统开始换页，玩家看到的是"启动器把我的电脑搞卡了"。
- 若在保存时静默把 7373 改成 4096：玩家永远不知道自己填的值被改，只会觉得"设置不生效"。
- 若做"一键释放"扫描所有进程：Chrome、编译器、游戏全部被页出，随后又全部页入，整机瞬间更慢。
