# ADR-0007：玻璃效果与性能边界（默认关闭，模糊只留在临时浮层）

- 状态：已采纳（第 80 轮）
- 关联轮次：第 60（崩溃卡片）、66–67（切页卡死与全禁特效）、80（液态玻璃）

## 背景

用户希望启动器有"液态玻璃"质感，同时明确要求**保障流畅度**、默认保持原主题、
开启前给出红字警告，并且不要重犯第 66/67 轮的错——那次是给卡片挂
`DropShadowEffect` + `BitmapCache`，隐藏页释放后每次切页都要重建整页位图，
一点就卡死，最后把整个特效类全禁了。

WPF 里"真玻璃"有两条路，都有代价：

1. **实时模糊**（`BlurEffect`）：它模糊的是**元素自己的子树**。加在卡片上，
   卡片里的文字一起糊；要"透出后面的窗口"得用 `VisualBrush` 抓背景快照，
   每次尺寸/内容变化都要重新光栅化——正是第 66 轮的病根。
2. **系统材质**（DWM Mica / Acrylic）：真正的 GPU 合成，成本≈0，但只有
   Win11 22H2+ 完整支持，Win10 只能 Acrylic 且观感不一致，远程桌面/虚拟机
   常常直接不可用；颜色与模糊程度不可自定义。

## 决策

1. **默认 `Off`**，配置文件不写也等于关闭；开启是显式动作，且任何非关闭模式
   先过 `GlassWarningWindow`（红框红字，**取消是默认按钮**），取消即回滚且不写配置。
2. **三种实现都给，但各自划清边界**：
   - `System`：`DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` → Mica；
     旧版本退 `SetWindowCompositionAttribute` + Acrylic。失败自动回落伪玻璃并
     把原因写进设置页/日志，**不留半透明空窗**。
   - `Faux`：对角渐变 + 程序生成 64×64 噪点 + 半透明表面刷 + 1px 高光边。
     全是纯色/位图填充，**零 Effect、零动画、零 BitmapCache**，刷子全部 Freeze。
   - `Local`：表面同样半透明，但窗口底色不变；只在 Ctrl+K 面板打开时对
     `PageHost` 挂一次**冻结的** `BlurEffect`（此时页面静止，只渲染一次），
     关闭立即摘除。常驻页面永远不模糊。
3. **可逆性**：表面刷写进一个专门放在 `MergedDictionaries` 末尾的覆盖字典，
   关闭时整本移除。直接写 `Application.Resources` 会把旧主题颜色钉死，
   之后切主题就会失效——冒烟专门断言了"恢复后颜色一致 + 字典已摘除"。
4. **守卫从"全禁"改为"白名单"**（`GlassGuardPolicy`，纯逻辑可测）：
   `<BlurEffect>` 只允许出现在 `MainWindow.xaml` 且必须挂在 `x:Name="Glass*"`
   元素上；出现在任何 `DataTemplate` 内一律违规（列表行就是当年卡死的那类）；
   C# 侧只允许 `MainWindow.xaml.cs` 且所在行含 `GlassBlur` 标记。
   `DropShadowEffect` / `BitmapCache` / 样式级 `Effect` 仍然全禁。

## 后果

- 正面：想要观感的用户有三级台阶可选（系统材质最像、伪玻璃最稳、仅浮层最保守）；
  默认用户完全不受影响；一旦卡顿改回「关闭」即可，无需重启。
- 代价：伪玻璃不会真的透出后面的窗口；`System` 模式在 Win10/远程桌面下的
  观感不由我们控制（已如实告知并自动降级）。
- 防线：#86（模式矩阵与降级）、#87（模糊白名单正反例）、`--glass-smoke`
  （着色可逆 / 刷子已冻结 / 红色警告可渲染 / 设置项已接线）。

## 反例（如果不这么做）

- 若允许"给 Card 加 BlurEffect 实现磨砂"：每个卡片都成为一个离屏渲染目标，
  滚动列表时逐帧重建，直接回到第 66 轮"切一次页面就卡死"的老路。
- 若直接改 `BgBrush` / `PanelBrush` 到 40% 不透明而不给警告：浅色主题下
  次要文字对比度不足，用户会觉得"启动器坏了"却找不到原因。
- 若系统材质失败后保留 `Background=Transparent`：Win10 + 远程桌面下会得到
  一个没有任何背景的窗口（不是"没效果"，而是"看不清"）。

## 第 81 轮修订（视觉重构）

第一版实现只把**面板**改成半透明，文字仍用主题里的深灰——浅色主题下就是
"白卡片 + 看不清的字"，用户直接判定为"丑"。修订如下，结论都写回上文：

1. **玻璃是一次完整的皮肤替换，不是局部调色**：开启后同时换掉 14 个画刷
   （面板、输入框、边框、Chip、导航高亮、以及 `TextBrush` / `TextMutedBrush`），
   文字变白 / 灰白。只改背景不改文字，等于没做。
2. **真实观感靠"底下的光"**：窗口先画一张矢量光影壁纸（`DrawingGroup` 四团极光
   + 噪点，全部 Freeze），卡片是 `#66000000` 半透明 + 上亮下暗的 1px 边缘
   （`CardEdgeBrush`），这比"均匀描边"更像玻璃厚度。全流程仍然零 Effect。
3. **无边框窗口自己做**：`WindowStyle=None` + `WindowChrome`（保留缩放/贴边），
   自绘标题栏拖动与三个窗口按钮；根容器用 `RectangleGeometry` 裁 12px 圆角，
   最大化时切直角。`AllowsTransparency` 是分层窗口，属于已知的渲染成本，
   在低端集显上需要实测（本轮只用截图验证了观感）。
4. **删掉 Mica**：壁纸铺满窗口后 DWM 材质没有可见表面，留着就是"选了没反应"。
   旧配置里的 `System` 折叠到玻璃皮肤，`DwmGlass.cs` 一并删除。
