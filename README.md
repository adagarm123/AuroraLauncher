# Aurora Launcher

一个从零自研、高性能的 **Minecraft Java 版启动器**（Windows）。

- 技术栈：**.NET 10 / C# 13 + WPF**，UI 与核心逻辑解耦（MVVM）。
- **零外部 NuGet 依赖**：仅使用 .NET 基类库（`System.Text.Json`、`HttpClient`、`System.IO.Compression` 等）。无网络可达性依赖，可离线构建。
- 许可：**MIT**。完全独立实现，未复用 PCL2 / HMCL 等受限制许可证项目的源代码（详见 `LICENSE`）。

## 最新一轮的更新内容
### 第 96 轮：下载管理不再「白茫茫」，以及一次必须承认的误判（2026-11-15）

**先更正你的判断：这次不是「防线抓到了假成功」，是我上一轮的防线误伤了真成功**

你截图里的报错「安装器运行结束，但没有生成可用的加载器版本文件」看起来很漂亮，但日志和磁盘说的不是一回事：

- `13:06:16` 预填充显示「29 个依赖已在本地」，`13:06:46`（30 秒后）就报错 —— 而正常情况下这套安装要 94~165 秒。
- 数据根目录里 `versions/1.20.1-forge-47.4.22/1.20.1-forge-47.4.22.json` **确实存在**（16.6 KB，13:06 由本次安装器重写），`mainClass=cpw.mods.bootstraplauncher.BootstrapLauncher`、`inheritsFrom=1.20.1`、29 个库齐全。
- 真正的原因：这个目录 **11:43 就已存在**。第 95 轮把「成功」改成了「必须检测到新建目录」，但 `created` 只包含本次新建的目录；老目录在 `existing` 集合里被排除，`detected=null` → 误报失败。

所以第 95 轮那条防线本身没错（拒绝把 URL 提示 id 当成已安装版本是对的），错在**只认新建、不认已有**。这一轮补上 `LoaderProfileLocator`：安装器跑完后若无新建目录，就扫描已有 `versions/`，挑出「MC 版本 + 加载器名 + 版本 token 都匹配、且 `<dir>/<dir>.json` 含 mainClass」的真实 profile 并认领，同时把真实 id 写回旧实例。你那个存着 `forge-1.20.1-47.4.22` 假 id 的实例，点一次补全就会被迁移到 `1.20.1-forge-47.4.22`。

**你对 UI 的诊断则完全成立**

「顶部正在安装 / 汇总 0% / 列表空白」三件事同源：`LaunchAsync` 的补全分支走的是**全局阶段表 + 手动 Status 字符串**（`InitStages(stages, title)`），而正常安装走的是 `InitStages(job, …)`。补全从来没进过 `DownloadJobManager`，失败时也只是抛一个全局异常，列表自然什么都没有。

**改法（单一状态来源）**

- 新增 `JobState.Preparing`。一点补全就 `Create + MarkPreparing`，列表立刻出现「准备中…」，聚合面板算作 1 个进行中（不再显示「当前没有下载任务」）。
- 补全整体包进 `RunRepairJobAsync`：进度、阶段、安装器日志里程碑都落到 Job 上；失败 `FinishJob(job, ex, false)` 留下红色任务行，成功才标完成。
- 顶部状态栏改绑 `HeaderText`：**有活跃任务时完全由 JobManager 驱动**（任务标题 + 实时阶段），无任务且是安装流程则回「空闲」；非安装类状态文本原样透传。Guard 锁死 XAML 绑定与「不许再用全局阶段表驱动补全」。
- **看门狗**：`JobWatchdogPolicy` 按阶段给超时 —— 准备中 30 秒、安装器下载 90 秒（实测下过 33 秒，30 秒会误杀）、运行阶段 15 分钟（官方安装器实测 94~165 秒静默，且它自己已有 15 分钟上限）。超时会中止底层 linked token、把任务标成失败并留在列表里，可原地重试。
- 「全部取消」加 `HasCancellableJobs` 的 `CanExecute` + XAML `IsEnabled`，没任务时置灰。
- 红色错误横幅新增「重试」按钮，直接重跑失败实例，不用再翻页面找入口。
- 导航高亮本来就是唯一 `CurrentPageKey` 驱动（`PageActiveConverter`），第二个淡紫是**鼠标悬停**不是状态分叉；现在 9 个导航项都加了只由同一个 key 生成的左侧竖条，active 与 hover 一眼可分，并由 `NavigationHighlight` 纯策略 + Guard 锁定单一来源。

**验证**

- `--unit` **135/135**、`--all` **142/142**（新增 6 项：已装 profile 认领、看门狗阈值、Preparing 聚合、导航单高亮，以及 2 条静态防线）
- **机制防线 34 条**；交互元素 117 → **118**（新增「重试」按钮）
- 发布：EXE + 95→96 补丁 + 签名清单（见文末）

**仍需你实测**：升级后对那个旧实例点一次「补全文件」，确认它被认领并能启动；以及真实网络卡住时看门狗与重试的手感。

## 快速开始

### 方式一：直接运行已发布的可执行文件（推荐）

已生成**单文件、自包含（self-contained）**&#x7684; Windows EXE：

```
publish/AuroraLauncher.exe   (约 63 MB，内含 .NET 运行时不需安装)
```

双击即可在 Windows 10/11 上运行，无需安装 .NET 运行时。首次启动会出现**新手引导**（检测 Java → 推荐版本一键安装 → 完成），老用户自动跳过。

### 方式二：从源码构建

需要安装 [.NET 10 SDK](https://dot.net) 与 Windows（WPF 仅支持 Windows）。

```bash
# 构建桌面程序（Debug）
dotnet build src/AuroraLauncher.Desktop/AuroraLauncher.Desktop.csproj -c Debug

# 发布为单文件自包含 EXE（Release, win-x64）
dotnet publish src/AuroraLauncher.Desktop/AuroraLauncher.Desktop.csproj `
  -c Release -r win-x64 `
  -p:PublishSingleFile=true -p:SelfContained=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -o publish
```

### 运行自测（分层：unit 离线 / all 含网络集成）

```bash
dotnet run --project tests/AuroraSelfTest -c Debug -- --unit   # 78 项，离线、毫秒级、CI 必跑
dotnet run --project tests/AuroraSelfTest -c Debug -- --all    # 85 项，含 7 项网络集成
```

本地一键 CI 脚本：`scripts/run-tests.ps1`（`-Full` 跑全量）；GitHub Actions 见 `.github/workflows/selftest.yml`。

需要桌面会话的两项显式诊断（不进 CI）：

```bash
dotnet run --project tests/AuroraSelfTest -c Release -- --nav-smoke  # 真实样式字典 + 12 轮显隐冒烟
dotnet run --project tests/AuroraSelfTest -c Release -- --nav-bench  # 每页构建/首次显示/稳态切页耗时
```
